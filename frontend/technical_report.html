1. Executive Summary

QuizMaster is a premium, portfolio-grade Quiz Management & Examination Platform built as a frontend-only React single-page application. It demonstrates a fully functional two-role system (Student & Admin) with rich interactive features including timed quiz attempts, real-time score calculation, leaderboard rankings, printable certificates, and comprehensive admin dashboards with analytics.

The application is architected with a clean separation of concerns — all data access is isolated behind a single module (storage.js), making it trivial to replace the LocalStorage-based demo persistence with a real backend API (e.g., Node.js/Express/MongoDB) without changing any component code.

2. System Overview & Objectives

2.1 Purpose

QuizMaster serves as a comprehensive online examination platform designed for educational institutions, corporate training programmes, and self-assessment scenarios. It enables administrators to create, manage, and publish quizzes while providing students with a polished, interactive environment to attempt quizzes, review answers, track performance, and earn certificates.

2.2 Key Objectives

  • Role-Based Access Control — Distinct Student and Admin experiences with route-level guards.
  • Rich Quiz Experience — Timed attempts with question randomisation, answer shuffling, auto-save, and auto-submit.
  • Analytics & Insights — Admin dashboards with charts for attempts over time, registrations, category popularity, and per-quiz performance.
  • Backend-Ready Architecture — All data access flows through a single abstraction layer, enabling seamless migration to a REST/GraphQL API.
  • Premium UI/UX — Apple-inspired design system with dark/light themes, glassmorphism, micro-animations, and responsive layouts.

5. Module Descriptions

5.1 Authentication Module

Authentication is managed through AuthContext.jsx and the authentication functions in storage.js. The system provides:

  • Login — Credential matching via username/email + password, with role verification (Student/Admin).
  • Signup — Student-only registration with duplicate username/email validation. Controlled by a system setting (allowRegistration).
  • Session Persistence — A sanitised (password-stripped) session object is persisted to LocalStorage so users stay logged in across refreshes.
  • Account Blocking — Blocked users receive an explicit error message at login.
  • Role Mismatch Detection — Prevents a student from logging in as admin and vice versa.
Warning - Demo-Only Security: Passwords are stored in plaintext in LocalStorage purely for demonstration. A production deployment must replace this with server-side authentication using hashed passwords (e.g., bcrypt) and secure session tokens.

5.2 Quiz Engine (quizEngine.js)

The quiz engine manages the full lifecycle of a quiz attempt:

FunctionDescription
buildQuestionSnapshot(quiz) Creates an immutable copy of quiz questions with optional randomisation and answer shuffling. The correctIndex is remapped when answers are shuffled.
createSession(userId, quiz) Initialises a new in-progress session with a computed expiry timestamp and persists it.
saveProgress(session) Persists the current answers, flagged questions, and question index for crash recovery.
getActiveSession(sessionId) Retrieves a non-submitted session, enabling page refresh without data loss.
submitSession(sessionId) Finalises the session: calculates scores, creates an attempt record, removes the session.
autoSubmitSession(sessionId) Triggered when the countdown timer reaches zero — identical to manual submission.
countAttempts(userId, quizId) Returns the number of completed attempts for retake control.

5.3 Score Calculator (scoreCalculator.js)

A pure, framework-free module that computes quiz results. Features include:

  • Weighted Scoring — Supports per-question marks and negative marking.
  • Per-Question Breakdown — Each question tagged as correct, wrong, or skipped.
  • Alphabetic Grading — Maps percentage to grades (A+/A/B/C/D/F) with descriptive labels.
  • Time Utilities — formatClock() for countdown display, formatDuration() for human-readable durations, timeAgo() for relative timestamps.

5.5 Theme System

The theme system is built on CSS custom properties (variables) defined in index.css, toggled via a dark class on the html element. Key design decisions:

  • Token-Based Architecture — All colours are referenced through semantic tokens (e.g., bg-bg, text-text, bg-card) rather than hardcoded values.
  • Light Mode — Apple-inspired crisp palette: #f5f5f7 background, #0071e3 primary accent.
  • Dark Mode — Space Gray / Pro Obsidian high-contrast scheme: #090a0f background.
  • Bootstrap Sync — The data-bs-theme attribute is kept in sync so Bootstrap utilities respond to theme changes.
  • Persistence — Theme choice is saved via the DAL and restored on page load.

5.6 Route Guards

Four guard components control access throughout the app:

GuardBehaviour
HomeRedirect Redirects / to /user or /admin based on role; guests go to sign-in.
GuestOnly Wraps auth pages; redirects already-authenticated users to their dashboard.
UserGuard Protects all /user/* routes. Requires role === 'user'.
AdminGuard Protects all /admin/* routes. Requires role === 'admin'.

All guards display a PageSkeleton loading state while the auth context initialises, preventing flash-of-wrong-content. Role mismatches redirect to the user's own dashboard rather than showing an error page.

12. Known Limitations

  1. Admin Quiz Preview: The admin "Preview" action navigates to the student quiz page, which is role-guarded for students. Admins are redirected to their dashboard. A production build would introduce a shared, read-only preview route.
  2. LocalStorage Size Limits: Browser LocalStorage is typically capped at 5 to 10 MB. Heavy usage with many photo uploads could exceed this limit.
  3. Single-Device Sessions: Since data is stored in the browser, progress is not synchronised across devices or browsers.
  4. No Server-Side Rendering: The app is a pure SPA with no SSR, which impacts initial load performance and SEO (not critical for an authenticated platform).
  5. Demo Seed Data: The seed() function generates synthetic attempt data with random distributions; this is clearly marked and would not exist in production.
  6. No Real-Time Features: Leaderboards and analytics update on page load, not via WebSockets or polling.
